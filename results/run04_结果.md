## 命中的用例

17 个在 bug 版失败、修复版通过。分两类：

**类型一：ü 与 5 双特殊叠加（路径 B×B）**
```python
@pytest.mark.parametrize('src, expected_v, expected_u', [
    ('lv5',   'v',  'ü'),
    ('lve5',  've', 'üe'),
    ('nve5',  've', 'üe'),
])
def test_finals_v_and_five_both_from_input_path_b(src, expected_v, expected_u):
    """路径 B×B：输入同时自带 v 和 5。"""
```

**类型二：5 由输入携带（路径 A×B 对照）**
```
to_tone2('sha5ng')   BUG='sha5ng'   FIX='shang'
to_tone3('tou5')     BUG='tou5'     FIX='tou'
```

关键在 AI 主动区分了两条路径并**分别构造**：

| 特征 | 路径 A（参数产生） | 路径 B（输入自带） |
|---|---|---|
| 轻声 5 | `neutral_tone_with_five=True` | 输入 `'sha5ng' 'shang5' 'de5'` |
| ü 写成 v | `v_to_u=False` | 输入 `'lv4' 'lve4' 'lv5'` |
| ü 写成 u | 无参数可产生（只有 B） | 输入 `'jūn' 'ju1n' 'yua2n'` |

**issue #290 的根因正则只在解析输入时被调用——只有路径 B 能触发。**
前三轮全部只覆盖路径 A，所以碰不到。

## 一个反直觉的副产物：命中率与杀伤率脱钩

| | 变异杀伤率 | 真 bug 命中 |
|---|---|---|
| 项目自带 141 测试 | 56.8% | 0 |
| run01 / run02 | **81.1%**（最高） | 0 |
| run03 | 51.4% | 0 |
| **run04** | 67.6% | ✅ **17** |

**杀伤率最高的两轮，一个 bug 都没抓到；抓到 bug 的那轮，杀伤率只排第二。**

原因：变异测试注入的是**单点变异**，考的是单维覆盖密度；
而真实 bug 藏在**多特征交叉 + 特定进入路径**上，是另一个维度的能力。

> **任何用覆盖率或变异杀伤率当质量门禁的团队，都应该看一眼这张表。
> 这两个指标测的不是同一件事，高的那个不保证低的那个。**

## 可复用的 prompt 模式（三条指令）

```
① 只给规格文档和函数签名，不要给实现源码。
   期望值必须来自「按规范这个函数应该返回什么」。

② 枚举输入的特征维度，并构造维度之间的两两交叉。
   特别注意两个「本身就是特殊情况」的取值叠加。

③ 对每一个特征，枚举它进入函数的路径：
   - 路径 A：由参数控制产生
   - 路径 B：由输入数据自带
   同一特征走两条路径时，函数内部很可能是「生成」和「解析」两套代码。
   必须分别构造用例，并把「自带该特征的数据」直接作为输入传入。
   若某特征既能由参数产生又能出现在输入串中，两条路径都必须测。
```

**代价**：用例数从 426 涨到 1019（2.4 倍），token 成本相应上升。
换来的是从 0 命中到 17 命中。
