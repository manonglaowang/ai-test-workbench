# 维度枚举引导问题

按类型挑用，目的是逼出**互相独立**的维度，而不是罗列输入样例。

## 通用

- 输入有哪几种**形态/格式/风格**？它们之间可以互转吗？
- 有哪些**可选参数**？每个参数都是一个独立维度
- 有没有**已废弃但仍支持**的旧参数？它和新参数的优先级是什么？
- **边界值**：空、零、负、极大、单元素、超长
- **类型边界**：None、可变对象、相等但不同一（`1` vs `1.0` vs `True`）

## 字符串 / 解析类

- 字符集：ASCII / 非 ASCII / 特殊符号 / 需要转义的字符
- 同一语义的**多种书写形式**（如 `ü` 与 `v`）← 高频 bug 源
- 位置：首 / 中 / 末 / 不存在
- 长度：空串 / 单字符 / 超长

## 容器 / 状态类

- 容量：0 / 1 / 未满 / 恰好满 / 超出
- 键的新旧：**新键 / 已存在的键** ← 高频 bug 源
- 元素大小的**计算方式**，以及它**写入后是否会变**
- 触发变化的方式：显式操作 / 时间推进 / 达到阈值自动触发

## 时间 / 生命周期类

- 不推进 / 推进到临界前 / **恰好等于临界** / 超过临界
- 生命周期由谁决定：构造参数 / 每条目独立 / 依赖数据内容
- 中途被修改的生命周期

## 数值类

- 0 / 正 / 负 / 极大 / 极小 / 精度边界 / 溢出

---

## 交叉的优先级

不必穷举所有两两组合。**优先交叉这几类**：

1. **两个都是「特殊情况」的取值** —— 单独都正常，叠加才出问题
2. **一个格式维度 × 一个数值/状态维度**
3. **一个参数开关 × 一个数据特征**

## 路径判定清单

对每个特征逐条过：

- [ ] 它能不能由某个**参数**产生？（路径 A）
- [ ] 它能不能**已经存在于输入数据**里？（路径 B）
- [ ] 它能不能通过**对同一对象的重复操作**出现？（路径 B）
- [ ] 它能不能通过**时间推进 / 外部状态改变**出现？（路径 B）
- [ ] 以上有两条以上成立 → **每条都要单独写用例**
