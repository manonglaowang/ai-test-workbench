# 实验协议

> 数据可信的前提是协议先定死。跑之前定，跑完不改。

## 一、实验问题

**AI 能不能发现真实开源项目里、当时没被发现的 bug？**

## 二、被测对象

| 项 | 值 |
|---|---|
| 项目 | [pypinyin](https://github.com/mozillazg/python-pinyin) (MIT, 5.3k★) |
| 目标模块 | `pypinyin/style/_tone_convert.py` + `_constants.py` |
| **实验 commit** | `a8878ec` (2022-12-24) —— bug 仍存在 |
| 修复 commit | `05eacb3b52ae` (2023-01-14, "Fixed #290") |
| 对应 issue | [#290](https://github.com/mozillazg/python-pinyin/issues/290) |

**已验证**：在 `a8878ec` 上，issue 描述的 7 个 case 全部复现。

**Bug 本质**：`RE_TONE2` / `RE_TONE3` 正则字符类漏了 `ü`
```
- RE_TONE2 = re.compile(r'([aeoiuvnmê])([1-5])$')
+ RE_TONE2 = re.compile(r'([aeoiuvnmêü])([1-5])$')
```

## 三、双轨测量

### 轨道 A：时间旅行（能不能发现真 bug）

AI 只看 `a8878ec` 的代码和文档，**不给任何 issue 信息**，生成 pytest 用例。
判定：生成的用例里有没有断言命中 issue #290 的 7 个 case 之一。

**盲测纪律（关键）**：
- ❌ 不告诉 AI 有 bug
- ❌ 不提 issue #290、不提 `ü`、不提「声调」「边界」等引导词
- ❌ 不给修复后的代码
- ✅ 只给：模块源码 + 该版本的 docstring/文档
- ✅ prompt 固定，全程存档

### 轨道 B：变异测试（用例质量的客观量化）

对目标模块注入变异（`>`→`>=`、删边界分支、改索引、改字符类），
用 AI 生成的用例集去跑，看能杀掉多少。

**杀伤率 = 被杀死的变异体 / 有效变异体总数**

对照组：项目自带测试套件 + 维护者在修复 commit 里补的 146 行回归测试。

## 四、指标（跑之前定死，不许事后加）

| 指标 | 定义 |
|---|---|
| 命中真 bug | 是 / 否 —— 有无用例断言命中 #290 |
| 生成用例数 | AI 产出的 test 函数个数 |
| 语法可执行率 | 能被 pytest 收集的 / 总数 |
| 首次跑通率 | 首轮无需人工修改即通过的 / 可执行的 |
| 误报数 | 断言了错误期望值的用例数（把正确行为判为失败） |
| 需人工修改比例 | review 后必须改的 / 总数 |
| **变异杀伤率** | 轨道 B |
| **对照杀伤率** | 项目自带测试的杀伤率 |
| 耗时 | 墙钟时间 |
| token 成本 | 输入/输出 token 与费用 |

## 五、如实记录原则

- 数据难看照发。**失败率本身就是这类内容最缺的东西。**
- 每轮 prompt、原始输出、完整日志全部存 `runs/`
- 人工修改用例必须记录改了什么、为什么
- 实验协议定后不改；确需调整则**另起一轮**并说明原因

## 六、可复现

任何人 `git clone` 后按 README 能完整重跑，得到同量级结果。
